# Security Policy

[简体中文](SECURITY.zh-CN.md)

## Supported versions

Security fixes are provided for the latest published version of Math Chords. Please
confirm that an issue is reproducible on the latest release before reporting it.

## Reporting a vulnerability

Do not report security vulnerabilities through public GitHub issues, discussions, or
pull requests.

Use [GitHub private vulnerability reporting](https://github.com/ichenh/obsidian-math-chords/security/advisories/new)
to send the maintainer a confidential report. Include:

- the affected Math Chords and Obsidian versions;
- the operating system and relevant plugin settings;
- clear reproduction steps or a minimal proof of concept;
- the expected impact and any known mitigations; and
- whether the vulnerability has been disclosed elsewhere.

Remove private vault content, credentials, tokens, and other unrelated sensitive data
from the report. If private vulnerability reporting is unavailable, use a private
contact method published on the [maintainer's GitHub profile](https://github.com/ichenh).

The maintainer will acknowledge a complete report when practical, investigate it, and
coordinate remediation and disclosure based on severity. Please allow time for a fix
before making the report public.

## Scope

Reports about the Math Chords source code, release artifacts, update process, or unsafe
handling of note content are in scope. Vulnerabilities in Obsidian, MathJax, GitHub, or
other third-party services should be reported to their respective maintainers unless
Math Chords introduces the vulnerable behavior.
